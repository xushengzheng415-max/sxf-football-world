> 状态：产品边界已冻结，代码尚未开始修改

## 一、背景与目标

「赛小蜂足球世界」目前有两个入口：

- 服务号 H5：`service-account-h5/card-world/index.html`
- 独立小程序：`miniprogram-world`，AppID `wxa0ac7d45bcabd140`

原 H5 照搬了小程序的「我的主卡 / 卡册签约 / 组阵」玩法，职责重叠，且付费能力散落在 H5。现明确拆分：

- **H5 = 个人卡库 + 更衣室**：看自己的球员卡、换背景/皮肤、裁剪照片、进入小程序。
- **小程序 = 轻社交玩法 + 全部付费**：签约、组阵、对战、赛事、会员、蜂蜜、照片合成扣费。

目标：

1. H5 不再承载任何交易。
2. 会员权益在 H5 与小程序之间准确衔接。
3. 5 人制免费，8/11 人制与城市赛/社区赛/线上对抗归会员。
4. 一期不做通行证、不做抽卡、不做皮肤直购。
5. 不替换本地完整版 `cardWorld.cjs` 引擎。

## 二、冻结的产品规则

### 2.1 两端职责

| 能力 | H5 个人仓库 | 小程序 |
|---|---|---|
| 查看本人球员卡、卡库 | 可 | 可 |
| 换背景 / 换皮肤 | 可用已拥有的；会员权益可用 | 可 |
| 照片上传、裁剪、远近、预览 | 可 | 可 |
| 照片合成并启用、蜂蜜扣费 | 不可 | 可 |
| 设为主卡 / 切换展示卡 | 可 | 可 |
| 签约、组阵、对战、赛事 | 不可 | 可 |
| 会员开通 / 续费 | 不可，只显示状态 + 去小程序 | 可 |
| 蜂蜜充值、皮肤购买 | 不可 | 可 |
| 价格、订单、支付按钮 | 一律不出现 | 可 |

### 2.2 H5 禁止项

- 不展示价格、折扣、订单、支付、充值、购买入口。
- 不调用任何下单、支付、退款、蜂蜜充值接口。
- 不出现「去公众号/H5 支付」或外部支付链接。
- 照片合成扣费不在 H5 发生。

### 2.3 付费与权益

| 能力 | 免费用户 | 会员 |
|---|---|---|
| 5 人制组阵与比赛 | 可用 | 可用 |
| 8 人制 / 11 人制组阵与比赛 | 锁定 | 可用 |
| 城市赛 / 社区赛 | 锁定 | 可用 |
| 线上虚拟比赛 / 虚拟对抗 | 锁定 | 可用 |
| 会员专属背景 / 皮肤 | 灰显 | 可用 |
| 赛季皮肤（已领取） | 赛季内可用；赛季结束灰显 | 赛季结束仍可用 |
| 赛季皮肤续费后 | 恢复可用 | 恢复可用 |

补充：

- 会员只恢复**已拥有**赛季皮肤的可用性，不赠送未领取皮肤。
- 会员皮肤不写永久拥有记录，按会员有效期实时判定。
- 后台撤销的皮肤与「会员到期/赛季结束」分开处理：撤销后即使续费也不恢复。
- 装备引用不清空，读取时回退；续费自动恢复。

### 2.4 赛季皮肤获取（一期）

- 赛季期间完成**固定任务**领取，例如观赛、训练打卡、球队任务。
- 固定奖励，无概率、无付费、无盲盒。
- 一期不做付费通行证、不做皮肤直购、不做抽卡。
- 赛季结束后记录保留，卡面灰显；有效会员可继续使用。

### 2.5 线上对抗与赛事（一期）

- 线上虚拟比赛一期只做**异步模拟结果**，不做实时 PvP。
- 城市赛/社区赛一期只做**平台自办或平台代报名**；第三方主办赛事的会员门槛另行合规评估。
- 已报名且已开始的赛事，会员到期不中途取消资格；未开始的新报名到期拦截。

## 三、会员主键与权益衔接

### 3.1 现状问题

- 会员订阅 `subscriptions` 目前按**服务号 officialOpenId** 存储。
- 小程序虚拟支付拿到的是**小程序 openId**，不保证与服务号 openId 相同。
- 不统一主键会出现「小程序是会员、H5 不是会员」。

### 3.2 采用方案 A

- 会员主键统一为 `users._id` 或 `unionId`。
- `officialOpenId` 作为别名/兼容键保留。
- 读取顺序：主键 → officialOpenId 兼容读取。
- 写入：新数据写主键，同时保留 officialOpenId 索引字段。
- 迁移：分批回填，提供脚本与回滚说明；不做一次性破坏性迁移。
- H5 用 `session.serviceAccountOpenId` 解析到统一主键后读取会员状态。

### 3.3 权益输出

统一权益模块输出，前端只展示，不自行判断：

```js
{
  maxLineupSize: 5 | 8 | 11,
  eventTiers: ['city', 'community', 'online'],
  continueSeasonSkins: true
}
```

服务端必须在以下四处校验，不能只锁 UI：

1. 保存阵容
2. 发起比赛
3. 赛事报名
4. 线上对抗匹配

## 四、皮肤体系

### 4.1 范围

- **平台级**皮肤，不按球队/赛事绑定。
- 皮肤只改变外观，不改变球员数据、能力或比赛结果。
- 复用现有球员卡渲染管线（背景、遮罩、排版、crop、动态卡、箔光），不新建一套渲染。

### 4.2 状态机

```js
skinState:
  available             // 可装备
  not_owned             // 未拥有
  expired_membership    // 会员到期，灰显，续费恢复
  expired_season        // 赛季结束且非会员，灰显，续费恢复
  revoked               // 后台撤销，灰显，续费不恢复
  unpublished           // 已下架
```

读取时同时返回：

```js
{
  equippedSkinId,     // 用户原本选择的
  effectiveSkinId,    // 实际渲染的；回退时为空
  skinState,
  skinReason          // MEMBERSHIP_REQUIRED / SEASON_ENDED / SKIN_REVOKED
}
```

规则：

- 不可用时渲染回退到基础卡/铜银金卡面。
- 不写库、不跑定时任务、不清空 `players.playerCardDisplayTemplateId`。
- 只有用户主动选择其他皮肤或基础卡面时才更新装备字段。
- 会员续费后下一次读取自动恢复。

### 4.3 数据模型建议

`card_skin_products`（平台级目录）

- `_id` / `skinId`
- `title`
- `previewFileId`
- `templateId`（对应已发布模板）
- `category`: `member` | `season` | `limited`
- `status`: `draft` | `published` | `offline`
- `seasonId`
- `memberRequired`
- `acquireRule`: `none` | `season_task`
- `sort`
- `createTime` / `updateTime`

`card_skin_ownership`（拥有关系）

- `_id`
- `userId`（统一主键）
- `skinId`
- `source`: `season_task` | `gift` | `purchase`（一期只启用前两种）
- `seasonId`
- `status`: `active` | `revoked`
- `acquiredAt`
- `expiresAt`（赛季结束时间，可空）
- `grantRef`

说明：

- 会员皮肤不写拥有记录，按会员状态实时计算。
- 拥有关系记在 `userId`，装备记在 `playerId`；一期同一用户多个球员可共用。
- 装备复用 `players.playerCardDisplayTemplateId`，通过皮肤对应的 `templateId` 写入。

### 4.4 运营后台

新增「卡面皮肤中心」，与现有「球员卡模板库 / 成卡库」并列：

- 皮肤列表：分类、会员专属、赛季、状态、排序
- 编辑器：复用现有背景/遮罩/排版/预览
- 发布/下架
- 赛季任务配置与发放
- 授权记录、撤销
- 一期**不做**价格、订单、退款

现有球员卡模板库继续只管球员数据卡，不掺皮肤。

## 五、H5 信息架构

### 5.1 页面

**1. 我的球员卡**

- 大卡面 + 箔光
- 姓名、号码、位置
- 数据中心统计：积分、出场、进球、助攻；未知显示「—」

**2. 卡面设置**

- 背景/皮肤列表：
  - 已拥有可选
  - 会员皮肤按会员状态可用
  - 过期灰显，提示「续费后恢复」
  - 未拥有不显示购买按钮，只提示「在小程序中获取」
- 照片：
  - 上传
  - 裁剪、缩放、远近
  - 预览
  - 底部主按钮「合成并启用（去小程序）」
- 只换背景或只裁剪可保存，不扣费

**3. 我的卡库（只读）**

- 已获得卡列表
- 查看卡面、设为主卡
- 不可签约、不可购买、不可删除
- 空态「还没有卡，去足球世界签约」

**底部入口**

- `wx-open-launch-weapp` 打开小程序 `wxa0ac7d45bcabd140`
- 需要公众号 JS-SDK 签名，不能只放普通链接

### 5.2 H5 数据流

- 会话：`localStorage.sxf_referee_h5_session` 作为 `serviceSessionToken`
- 入口统一走 `webLoginApi`
- 会员状态：`servicePrivateMembershipStatus`，只读
- 卡库：`listMyPlayerCards` / `getMyPlayerCard` / `previewMyPlayerCard`
- 设为主卡：`cardWorldSetMainCard`
- 换背景/裁剪：`saveMyPlayerCard` 的免扣费路径
- 照片草稿：新增上传接口
- 照片合成：跳小程序，H5 不调用扣费接口

## 八、照片流程（方案 A）

### H5

1. 用户上传照片
2. 服务端抠图，生成草稿文件
3. H5 裁剪、缩放、远近、预览
4. 草稿只存临时记录，不改正式形象照
5. 点击「合成并启用」跳小程序

### 小程序

1. 读取草稿
2. 展示最终效果与蜂蜜消耗
3. 用户确认
4. 扣蜂蜜；失败退款
5. 写正式形象照与卡面版本
6. 返回 H5 刷新

### 规则

- 满 100 分免费、否则默认 100 滴蜂蜜，沿用现有常量，后续可调。
- H5 不允许触发扣费。
- 未确认草稿不写正式数据。
- 草稿过期自动清理。

## 九、合规红线

1. **虚拟商品支付**
   - 小程序内虚拟商品/付费功能必须走小程序虚拟支付。
   - 不得引导到 H5、公众号、外部网站完成支付。
   - 会员开通入口迁入小程序前，H5 不展示价格与支付按钮。

2. **抽奖与盲盒**
   - 不做抽卡、概率开卡、盲盒。
   - 赛季皮肤固定任务领取，无随机。

3. **游戏类目**
   - 线上对抗一期只做异步模拟。
   - 不做实时 PvP 前先评估类目与版号问题。
   - 不得用包装文案规避审核，按实际功能选择类目。

4. **未成年人**
   - 会员购买、蜂蜜消费需遵守未成年人保护要求。
   - 赛事报名涉及未成年人时需监护人确认。

5. **赛事收费**
   - 城市赛/社区赛若为第三方主办，会员门槛与报名规则需单独评估。
   - 收费主体、退费规则、发票与赛事资格说明要明确。
